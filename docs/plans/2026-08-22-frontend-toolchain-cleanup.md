# Frontend Toolchain Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Shrink and freeze the frontend toolchain (remove Storybook, pin dependencies), delete dead HTMX-era code, make CI actually run the web unit tests, and true-up the migration docs — with an optional final phase adding a data-driven `DataTable` to de-bloat the CRUD pages.

**Architecture:** No runtime architecture changes. The Svelte 5 islands pattern, Go-template shells, and `go:embed` asset serving all stay exactly as they are. This plan removes tooling and dead code around them, and (Phase F) adds one new component that composes the existing Table primitives.

**Tech Stack:** Go 1.22+, Svelte 5, Vite 6, Vitest 4, Playwright, Tailwind v4. Node required only for work inside `web/`.

**Spec:** No standalone spec — requirements come from the 2026-08-22 conversation with Harper. Summary of agreed decisions:
1. Svelte stays; embedded serving stays; `web/` stays in this repo.
2. Storybook is removed (churn king: 4 packages, already forced one major upgrade mid-migration). Design doc decision #9 pre-authorized the fallback: "Falls back to Playwright screenshots if setup is painful."
3. All remaining npm deps get exact version pins; updates become deliberate (scheduled or CVE-only), policy recorded in CLAUDE.md.
4. Dead HTMX scaffolding in `auto.ts` and stale HTMX comments in `webadmin.go` are removed/corrected. HTMX itself is already gone (zero `hx-` attributes, not loaded).
5. `chat_app_v2.html` is renamed to `chat_app.html` (history-based names violate naming rules; no v1 exists — earlier belief that an orphaned `chat_app.html` existed was wrong, verified by grep 2026-08-22).
6. Phase docs 3–5 get truthful `**Status:**` lines with verification evidence; CLAUDE.md's frontend section is updated (current phase, commands, learnings).
7. CI gains a `npm test` step so the replacement unit tests actually gate PRs. (Scope note: this adds one step to the existing `ci.yml` test job. It does NOT touch docker.yml or release.yml — the gotchas.md CI-scope rule concerns expanding release/Docker workflows, which this plan deliberately avoids.)
8. Phase F (severable, decide at its gate): `DataTable` component + migration of simple CRUD pages.

## Global Constraints

- Branch: all Phase A–E work on `chore/frontend-toolchain-cleanup`, branched from `main`. Phase F, if executed, goes on its own branch `feat/datatable` after A–E merge.
- Conventional commits, imperative present tense. Never use `--no-verify` or any hook-bypass flag.

- Zero new warnings in test output. If a pre-existing failure is found (see Task 1), STOP and report before proceeding — do not silently work around it.

```typescript
// Axe accessibility scans against the running app (not Storybook).
// Pre-existing violations: add the page to KNOWN_ISSUES with a comment and
// report them — fixing them is separate work, not part of toolchain cleanup.
import { test, expect } from '@playwright/test';
import AxeBuilder from '@axe-core/playwright';

// pages with documented pre-existing violations, excluded pending fixes
const KNOWN_ISSUES: Record<string, string[]> = {
  // '/admin/agents': ['color-contrast'],  // example shape
};

async function scan(page: import('@playwright/test').Page, path: string) {
  await page.goto(path);
  let builder = new AxeBuilder({ page });
  for (const rule of KNOWN_ISSUES[path] ?? []) builder = builder.disableRules(rule);
  const results = await builder.analyze();
  expect(results.violations).toEqual([]);
}

test('login page has no axe violations', async ({ page }) => {
  await scan(page, '/login');
});

// Authenticated pages: use the same auth helper admin.spec.ts uses,
// then scan '/', '/admin/', '/admin/agents', '/admin/threads'.
```

```svelte
<script lang="ts" generics="T">
  import type { Snippet } from 'svelte';
  import Table from './Table.svelte';
  import TableHead from './TableHead.svelte';
  import TableBody from './TableBody.svelte';
  import TableRow from './TableRow.svelte';
  import TableHeader from './TableHeader.svelte';
  import TableCell from './TableCell.svelte';

  export interface DataColumn<T> {
    key: string;
    header: string;
    align?: 'left' | 'center' | 'right';
    cell?: Snippet<[T]>;
  }

  interface Props {
    columns: DataColumn<T>[];
    rows: T[];
    rowKey: (row: T) => string;
    class?: string;
  }

  let { columns, rows, rowKey, class: className = '' }: Props = $props();

  function plain(row: T, key: string): string {
    const v = (row as Record<string, unknown>)[key];
    return v == null ? '' : String(v);
  }
</script>

<Table class={className}>
  {#snippet children()}
    <TableHead>
      {#snippet children()}
        <TableRow>
          {#snippet children()}
            {#each columns as col (col.key)}
              <TableHeader align={col.align}>
                {#snippet children()}{col.header}{/snippet}
              </TableHeader>
            {/each}
          {/snippet}
        </TableRow>
      {/snippet}
    </TableHead>
    <TableBody>
      {#snippet children()}
        {#each rows as row (rowKey(row))}
          <TableRow>
            {#snippet children()}
              {#each columns as col (col.key)}
                <TableCell align={col.align}>
                  {#snippet children()}
                    {#if col.cell}{@render col.cell(row)}{:else}{plain(row, col.key)}{/if}
                  {/snippet}
                </TableCell>
              {/each}
            {/snippet}
          </TableRow>
        {/each}
      {/snippet}
    </TableBody>
  {/snippet}
</Table>
```

Notes for the implementer: the snippet nesting lives HERE, once, so call sites never write it again — that is the point of this component. `TableHeader`'s existing `align` prop: check its Props interface accepts the same union; if its prop name differs, use ITS name (do not change the primitive). If `svelte-check` rejects exporting an interface from a generic component script, move `DataColumn` to `web/src/lib/components/dataTable.ts` and import the type in both the component and its consumers — keep the exported names identical.
